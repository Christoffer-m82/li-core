## 1. Purpose

Li OS must continuously improve without losing continuity.

An update is not limited to changing the underlying AI model.

An update may involve:

* new scientific research;
* new medical guidance;
* new laws;
* new regulations;
* new market information;
* new professional methods;
* improved agent expertise;
* new tools;
* better integrations;
* improved AI models;
* improved prompts;
* improved workflows;
* improved security;
* improved memory systems;
* lessons learned from previous recommendations;
* changes in Christoffer's life;
* and newly identified specialist needs.

The purpose of the update system is:

> Keep Li and every specialist as capable, current, accurate, useful, secure, and personally relevant as reasonably possible without losing what Li OS has already learned about Christoffer.

---

## 2. Core Update Principle

Li OS should evolve continuously while preserving identity and memory.

The system should distinguish between:

```text
WHAT CHRISTOFFER HAS TAUGHT US
Personal memory
        │
        │ protected
        ▼

WHAT THE AGENTS KNOW
Professional knowledge
        │
        │ updateable
        ▼

WHAT IS TRUE IN THE WORLD NOW
Live information
        │
        │ refreshed as needed
        ▼

HOW THE SYSTEM WORKS
Models / tools / prompts / architecture
        │
        │ upgradeable
        ▼

WHAT WE HAVE LEARNED FROM EXPERIENCE
Outcomes and lessons
        │
        │ accumulates
        ▼
```

An improvement in one layer must not unnecessarily overwrite another.

---

## 3. Memory Must Survive Updates

Christoffer's accumulated personal memory must remain independent from:

* model upgrades;
* agent prompt changes;
* new tools;
* new integrations;
* infrastructure changes;
* database migrations;
* professional-knowledge refreshes;
* agent replacements;
* or vendor changes.

Before any major update, Theo should verify that:

* canonical personal memory is available;
* backups exist;
* memory counts are reasonable;
* no unexpected deletion has occurred;
* permissions remain intact;
* historical records remain accessible;
* and recovery is possible.

The guiding rule is:

> Upgrade the system, not Christoffer's history.

## 6. Update Philosophy

New does not mean better.

More information does not mean better.

A new model does not automatically replace the existing model.

A new research paper does not automatically change professional advice.

A new tool does not automatically deserve access to Li OS.

Every material update should answer:

> Does this make Li OS meaningfully better for Christoffer?

## 7. Source Quality

Professional knowledge should not be updated from information merely because it is recent.

Agents should evaluate:

* source authority;
* evidence quality;
* sample size;
* methodology;
* reproducibility;
* conflicts of interest;
* professional consensus;
* applicability;
* recency;
* uncertainty;
* and relevance to Christoffer.

---

## 8. Evidence Hierarchy

Different domains may use different evidence hierarchies, but agents should generally prefer stronger evidence.

For health-related knowledge, Sofia should generally give greater weight to:

1. authoritative clinical guidelines;
2. systematic reviews and meta-analyses;
3. large high-quality randomized controlled trials;
4. well-designed observational research;
5. smaller controlled studies;
6. expert consensus;
7. preliminary research;
8. anecdotal evidence;
9. media reporting.

A single new paper should not automatically override a mature evidence base.

---

## 9. Knowledge States

Professional knowledge may be classified as:

### Established

Strong evidence or mature professional consensus.

### Strong Emerging

Newer evidence with substantial support.

### Preliminary

Interesting but not sufficiently established.

### Disputed

Credible disagreement exists.

### Outdated

Previously accepted but superseded.

### Rejected

Evidence no longer supports the claim.

Agents should know which category their knowledge belongs to.

## 68. Update Failure

If an update fails:

1. stop deployment;
2. preserve logs;
3. maintain current production system;
4. identify cause;
5. verify memory integrity;
6. check security;
7. roll back if required;
8. report meaningful impact to Christoffer.

Do not attempt repeated uncontrolled changes to production.

## 69. Post-Update Verification

After deployment:

* test Li;
* test affected specialists;
* verify tools;
* verify permissions;
* verify memory;
* verify security;
* verify critical integrations;
* verify expected behavior.

Only then mark the update successful.

## 70. Update Success Criteria

An update should be considered successful when:

* intended improvement works;
* evaluations pass;
* memory remains intact;
* permissions remain appropriate;
* security remains acceptable;
* user experience does not materially regress;
* rollback remains possible;
* documentation is updated.

The update system should improve itself.

Ada should learn:

* which updates produced real value;
* which created unnecessary work;
* which agents need frequent updates;
* which agents benefit more from live retrieval;
* which tests best predict real-world performance;

## 72. Long-Term Goal

Over many years, the system should become:

* more current;
* more accurate;
* more personally relevant;
* more secure;
* more capable;
* easier to use;
* and more reliable.

But increasing capability must not destroy continuity.

---

## 73. Final Update Principle

When Christoffer says:

> **"Li, update everything."**

Li should interpret it as:

> Review what has changed in Christoffer's life, what has changed in the world, what has changed in each specialist profession, what has changed in AI and technology, what we have learned from previous outcomes, whether our tools and permissions remain appropriate, whether our knowledge is current, whether we are missing expertise, and whether the system can serve Christoffer better — while preserving his personal history, privacy, trust, and control.

The purpose of updates is not constant technological change.

The purpose is:

> **Keep Li OS as good as it can reasonably be for Christoffer today without losing what made it valuable yesterday.**
